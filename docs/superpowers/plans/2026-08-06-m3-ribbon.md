# Dr. Markdown — Milestone 3 Ribbon Plan

**Date:** 2026-08-06
**Status:** Implementation note

## Architecture

The product target is a native macOS application, not a website. The overall
objective is a Microsoft Word level of features in an open-source markdown
editor that can toggle between WYSIWYG and raw markdown without losing fidelity.
M3 is the ribbon foundation for that objective: it organizes commands into a
Word-like surface while preserving markdown as the canonical document format.

M3 stays in the embedded Wails webview UI layer (`frontend/dist`), which is
packaged into the macOS `.app`; it is not a web deployment surface. The Go shell
remains responsible only for native file dialogs, atomic saves, dirty-state
guards, and window title updates. Ribbon actions are deterministic markdown
transforms over the canonical document text, then the active editor surface is
refreshed from that markdown. This keeps both WYSIWYG and raw mode on the same
command path and avoids coupling app code to unexported ProseMirror internals in
the vendored Crepe bundle.

Tabs are frontend document records:

- `id`, `path`, `title`, `savedText`, `dirty`, `markdown`
- one active document is mounted into either Milkdown or CodeMirror
- switching tabs stores the active editor text, then reloads the target tab

The ribbon is split by visible tabs:

- **File:** new, open, save, save as, close tab
- **Home:** block style, inline formatting, lists, indent/outdent
- **Insert:** table, code block, mermaid starter, link, horizontal rule
- **View:** WYSIWYG/raw mode, theme toggle, focus mode
- **Table Tools:** visible when the active markdown contains a GFM table

## Success Criteria

- Existing M1-M2 round-trip and dirty/open/save tests remain green.
- New e2e coverage proves tab switching preserves independent buffers.
- New e2e coverage proves ribbon commands insert expected markdown.
- New e2e coverage proves shortcuts route through the same commands.

## Known Tradeoff

Contextual table tools are context-aware at the document level in M3: they appear
when the active markdown contains a GFM table. Cursor-exact table detection would
require either a lower-level ProseMirror command surface in the vendor bundle or
a dedicated selection bridge; that belongs with a later editor-internals pass,
not as an ad hoc dependency on minified private symbols.
