# ABORT review — v1.6.3, "One surface, and a way to search it"

**Decision under review.** Ship dr-markdown v1.6.3 from frozen SHA
`7097eaee1bceadfb549099d932845ffd8ce95bef` (branch `release/v1.6.3`) as a public,
notarized macOS `.dmg`, replacing v1.6.2.

**Reversibility and blast radius.** The tag and the GitHub release are revertible.
**A downloaded binary is not**, and this product has no auto-update — a defect
that ships stays on a user's machine until they choose to download a later
release. The exposed party is anyone who opens a markdown file with it, and the
untrusted input *is* the document.

**Why this review is unusually long.** This tree was cut, tagged and published
once already, as 1.6.4, and withdrawn inside the hour on a prior review's
verdict. That review found four blockers. This one found five more — and three of
the five were introduced by the fixes for the first four.

---

## A — Premortem

> We shipped, and it failed because we treated "the review found four blockers"
> as "the review found all the blockers." Every one of those fixes touches the
> most dangerous surface in the product — the boundary between an untrusted
> document and the native file bindings — and each was written, tested and
> verified by the same author who wrote the defect it repairs, hours before the
> tag, on a version number already burned once that day. The warning sign
> ignored: each station called its own finding the *primary* chain, which should
> have read as "there are more," not "here is the one."

**The sentence that would have stopped the ship:** *"Nobody other than the author
has exercised any of these four fixes, and two of the gates that would catch a
mistake still require a human who has not run them."*

That sentence turned out to be the review. The quit fix — written to stop ⌘Q
discarding unsaved work — was verified only on its clean half. Its dirty half was
run by hand for the first time during this review and **wedged the application**:
no dialog, and afterwards neither ⌘Q nor the close button worked.

---

## B — Stations

Five independent stations, blind to each other, read the frozen tree.

| # | Station | Verdict | Blocking issue |
|---|---|---|---|
| 1 | Competitor / Attacker | **GO-WITH-CONDITIONS** | The release build is the harness build: Web Inspector live, driver JS injected, `__docfixture.md` file-read endpoint served |
| 2 | Worst-Case Customer | **NO-GO** | Replace-All revert snapshot has no document identity — ⌘Z after switching documents overwrites the wrong file, and the app reports success |
| 3 | Resource Auditor | **NO-GO** | In Split, a bare click changes what `getMarkdown()` returns, so find and replace run over a different string |
| 4 | Future Me (6 months) | **NO-GO** | Split silently loses the most recently typed characters when authority flips inside the debounce window |
| 5 | Domain / Integrity | **NO-GO** | Same as station 2, reached independently: the snapshot is not keyed to a document and no transition invalidates it |

Verdicts are recorded as returned. Two stations reached the undo defect
independently by different routes; that agreement is recorded rather than merged.

### Findings reproduced before being believed

Two were executed rather than reasoned about, because a chain that has not been
run is a hypothesis:

**Cross-document undo** — replace in document A, switch to B, press ⌘Z:

```
B before undo:  "BBB untouched BBB\n"
B after undo:   "AAA widget AAA\n"      ← document A's pre-replace text
```

B is left dirty, so the next save — or the quit guard's own Save button — writes
A's content to B's path. This is the failure class `internal/session/session.go`
was written to end, reintroduced one layer above where the session layer can see
it. `confirmNoExternalChange` cannot help: the file on disk still matches its
baseline, because the corruption came from inside the application.

**Split authority changes the document** — a `pointerdown` in the formatted pane,
with no edit at all:

```
source-authority:    "| a | b |\n| --- | --- |\n| 1 | 2 |\n\n\n\nafter three blanks\n"
formatted-authority: "| a | b |\n| - | - |\n| 1 | 2 |\n\nafter three blanks\n"
```

The frozen fidelity survey pins eleven constructs where the source and the
editor's re-serialization differ. Replace All then wrote the normalized string
back over the whole document — reflowing tables and collapsing blank-line runs
the user never touched, which is precisely the blast radius that routing replace
through the source was chosen to avoid.

### Root-cause clusters

1. **State captured without identity** (2, 6) — a snapshot and a debounced render
   both held *content* with no record of *which document* it came from. Leverage
   point: attach identity at capture, check it at use. Checking at use is what
   makes a transition path nobody remembered to update harmless.
2. **Two sources of truth** (3, 4) — Split has two live editors, and the code
   asked "which one is authoritative?" where it should have asked "what is the
   document?" Leverage point: one surface owns the text; the other is a view.
3. **Untested fix** (1) — the most dangerous cluster, because it was created by
   the previous review's remedy. A fix verified only on the path that cannot
   fail is not verified.
4. **Claim drift** (7, 9) — comments, README, in-app help and the architecture
   record each describe a product that existed earlier today.
5. **Build hygiene** (5) and **trusted producer** (10) — what the artifact
   carries, and what it exempts from its own guarantees.

### The one fix

**Attach identity where state is captured, and check it where state is used.**
That single change neutralises cluster 1 outright and is the shape of the fix for
cluster 2 as well: `getMarkdown()` stopped asking which pane is authoritative and
started reading the one surface that is always current.

### Acceptable risks

- **Mermaid `themeCSS` (10).** Real, and bounded by the CSP: `connect-src 'self'`
  and `img-src 'self' data: blob:` remove the exfiltration channels, and WebKit
  has no CSS-to-JS bridge. Ceiling is UI redress. Deferred because closing it
  means either sanitizing mermaid's output — a second sanitizer's worth of rules
  on markup we do not generate — or dropping diagram theming, and neither is a
  freeze-time change.
- **Injected driver JS still ships, inert (part of 5).** The mode globals are all
  false on a user launch, so it defines functions nobody calls. Deferred because
  separating it from the bridge it shares one string literal with is a refactor,
  and attempting a refactor under a freeze is how findings 1–4 happened. Build
  tags are the correct fix and are filed rather than rushed.
- **The WYSIWYG surface re-serializes the whole document on edit.** Carried
  forward unchanged and previously accepted. Only source-preserving editing
  closes the class.

### Dealbreaker

**YES.** Finding 1 — ⌘Q wedging the application with unsaved work on screen. It
is reachable by the primary quit gesture on macOS, it was introduced by this
release, and it is strictly worse than the defect it replaced: the old behaviour
lost your work, the new one lost your work *and* trapped you in the application.

## Closure

All ten conditions are met. What changed for the four that were open at the poll:

**C7 — the product's claims.** The README documented no find or replace at all,
described Split as "formatted preview/source switching" after that pane became
the real editor, and stated in five places that builds are unsigned and
un-notarized while the published releases are Developer ID signed, notarized and
stapled. It now says what the build does, and carries the two limits a user
actually meets: the Replace All revert is one step and belongs to the document it
was taken from, and find stops counting at ten thousand matches. The in-app
Shortcuts pane — headed "Implemented keyboard commands available in this build"
and listing seven, none of them Find — and the help dialog now list Find, Find and
Replace, next, previous, and the revert.

**C8 — the bundle rename.** Stated rather than fixed, and the distinction is the
point. A `.dmg` is a drag-and-drop image; it cannot remove anything, so no change
to the build script can make a new one replace an install of v1.6.1 or earlier.
The `--install` path already replaces by bundle identity. For the download path
the README's Download section and Known Limitations now tell the user to delete
the old `Dr. Markdown.app` by hand, and the release notes carry the same line.

**C9 — stated coverage.** `sanitize.js`, `render.js` and `app.js` each claimed to
cover "the split preview and the print surface". The split preview stopped
existing when Split became the editor, so a maintainer reading the sanitizer
would have believed an allowlist runs where it does not.

**C10 — the dialog gates, run by a human.** Both passed, and both judged the
guard's handling of the answer rather than merely that a dialog appeared:

```
QUIT:  gesture=terminate: mode=dirty guard=ALLOWED prompts=1 answer="Don't Save"
VERDICT: PASS — Don't Save allowed the close

CLOSE: mode=dirty guard=ALLOWED prompts=1 answer="Don't Save"
VERDICT: PASS — Don't Save allowed the close
```

The quit result is the one that matters: it is the gesture that wedged the
application earlier the same day, on the fix written to protect it.

### Found while closing the conditions

Three defects surfaced from chasing the gates rather than from the stations:

- **`-walk` had been failing since v1.6.2.** Forty UI checks against a real
  window, red because it still expected File to be a ribbon tab after File became
  a menu. Nobody saw it, because it was not in the release ceremony's list.
  Neither was `-gates`. Both are now, and File is checked on its own terms: that
  opening the menu does NOT disturb the ribbon, which is why it was moved.
- **`-doc` hung when given no path**, which is how it was first run. It printed
  one line to stderr and then sat on a window that could never load. It now
  refuses at the flag.
- **`-close-dirty` had no deadline.** It has never hung; the quit gate had never
  hung either, until it did, and the absence of a deadline is what turned that
  into a trapped maintainer rather than a verdict. Both have one now.

`-doc` also gained a recorded baseline against this repository's own README — 244
lines in, 244 lines out, `stable=true`, 13 differing lines every one of which is
table delimiter padding. It exits 1 whenever anything differs, which today is
always, so without a baseline it is unreadable as a gate.

### REVISED VERDICT: **GO**

**Confidence: 8/10.** Up from 3. What the two points are still for: the mermaid
`themeCSS` path remains accepted rather than closed, and the injected driver was
made conditional rather than removed by build tags — a decision taken to preserve
the recorded rule that the harness must drive the same binary a user gets.

**Project-lead summary:** the release is shippable — the dealbreaker is closed and
verified by hand on the gesture that broke, every other blocking finding is fixed
with a gate that can fail for it, and the three gates that turned out to be
decorative are now load-bearing.

**A note for the next release.** Two of this review's five findings were created
by the previous review's fixes, and three more were found only by running gates
nobody had run. That is not an argument against reviewing; it is an argument
against treating a fix as finished because it was written carefully, and against
believing a gate exists because it is in the repository. It exists when it is in
the ceremony and someone runs it.
