# ABORT Review — Round 7, cut v0.6.0

Candidate: `release/v0.6.0` off `develop`, 87 commits ahead of `main` at v0.5.1.
Date: 2026-08-25.

Rounds 1–6 are recorded in `docs/releases/v0.4.0-abort.md`, `v0.5.0-abort.md` and `v0.5.1-abort.md`.
Round 5 was the first five-of-five GO; Round 6 returned a NO-GO at Station 2, fixed it, and re-ran
the station.

This is the largest candidate yet: the application framework is gone, and the defect that blocked
the previous release is fixed.

## A — Assume Failure (premortem, written before the verdicts)

It is three months on and this release is the one people point at. The most likely reasons:

1. **The ribbon restructure broke muscle memory.** Home is gone. Someone who reached for it finds
   File, and the formatting controls they used are one tab further away than they were.
2. **The icon is wrong at a size the contact sheet did not show.** It is per-size artwork now, so
   there are two marks and a boundary between them at 64px. A Dock at a size nobody rendered would
   expose a seam.
3. **CSS `zoom` behaves differently in WebKit than in the Chrome the tests drive.** The zoom control
   was measured entirely in headless Chrome. The application runs on WKWebView.
4. **The Crepe bundle now carries four in-place patches** — the process shim, the undefined
   `basicSetup`, the One Dark palette, and the theme's cross-package `@import`s. Each fails loudly
   if its anchor disappears. None of them detects a refresh that still matches but has changed
   meaning.
5. **The packaged app was driven by a harness, not by a person.** This is the same premortem line as
   Rounds 5 and 6, and it is the line that found #53 after Round 5 shipped. It is *narrower* this
   time — the gates, the 40-check walk and the menu check all ran against this candidate — but a
   harness checks what someone thought to assert.

**Five of five GO on the first pass, with three named residuals.**

### Station 1 — Competitor / Attacker

Checked rather than asserted:

- The `Content-Security-Policy` line is **unchanged since `main`**.
- The only `fetch()` anywhere in the frontend is `vendor/theme/manifest.txt` — a local path. No
  `XMLHttpRequest`, no `WebSocket`, no absolute URL.
- `verify-vendor.sh` accounts for **29 files**, up from 25: the four ProseMirror stylesheets added
  this release, ~4KB in total.
- The standalone CodeMirror bundle was **deleted** — 377KB of third-party code that was fetched,
  digest-pinned and imported by nothing.

**This candidate closes a high-severity advisory, by deletion rather than upgrade.** GitHub reports
`github.com/labstack/echo/v4 < 4.15.3` — an encoded-slash route bypass exposing static files — on
the default branch. It is there as an **indirect dependency of Wails**:

```
main:      37 modules, including github.com/labstack/echo/v4 v4.13.3 // indirect
candidate: 10 modules, echo absent
```

`go mod why` reports the main module does not need it, and `go list -deps` puts it in no package's
closure. Removing the framework removed the vulnerable transitive dependency and 27 other modules
with it.

**Residual:** the Crepe bundle is patched in four places and therefore matches no upstream artifact.
The digest file is its only provenance, which is exactly why `verify-vendor.sh` runs on every push.

### Station 2 — Worst-Case Customer

The ribbon restructure is the change most likely to be felt. Measured by diffing every
`data-command` and `data-insert-command` between `origin/main` and this candidate:

```
lost   : none
gained : none
```

Everything moved; nothing disappeared. Zoom defaults to `1`, and an old preferences file that
predates the key simply falls through to that default.

**Residual, and it is a latent coupling rather than a live defect.** `settingsDraft` snapshots
`state.settings` when the modal opens and replaces it wholesale on save, so a setting changed
*outside* the modal while it is open would be reverted. Measured **not reachable** today — the scrim
covers the zoom control, `elementFromPoint` does not return it, and zoom survives a Settings save
(1.1 before, 1.1 after). It becomes reachable the moment any non-modal control is added that the
scrim does not cover.

### Station 3 — Resource Auditor

`VERSION` reads `0.6.0`, and rebuilding produced an `Info.plist` reading `0.6.0` without a second
edit — the single-source property holds. The Release Truth record carries nine required items and
four deferrals, each with a stated reason rather than a status. `architext validate` passes, and it
**caught a real inconsistency** on the way: marking 0.5.1 complete in the index without updating its
detail file.

### Station 4 — Future Me (6 months)

`gate3_boom` returns `REJECTED: panic in Boom` against the real host, so #61's failure mode cannot
recur silently. Every vendored patch exits non-zero with an explanation if its anchor disappears,
and each records what was measured and refuted so the next person does not re-derive it.

**Residual:** #62 and #63 remain open. A panic before the `App` exists leaves no trail, and a
repeating panic can evict the context needed to diagnose it. Both are deferred with reasons in the
Release Truth record.

## C — What the gates found that no test did

Recorded because it is the argument for driving the application at all, and because premortem
line 5 has now appeared three rounds running:

- **Four editor stylesheets never loaded** (#94). Crepe's theme `@import`s them from other npm
  packages by bare specifier and `vendor.sh` never fetched them, so ProseMirror's own base
  stylesheet, the table styles, the gap cursor and the virtual cursor 404ed in silence. A failed
  `@import` throws nothing and logs nothing. The host harness had been printing `ASSET MISS` all
  along; nothing read it.
- **The screen walk failed on `ribbon tab home activates`** after the restructure. `walk_darwin.go`
  is darwin-only, so CI compiles it and never runs it.

## C2 — Raised in review, after the stations ran

*"Aren't we meant to be eliminating wails altogether?"*

The dependency was gone and the stations had verified that. The **vocabulary** was not, and it was
worse than untidy: `crash.go`, `crash_test.go`, `app.js` and `links.js` each asserted the framework's
behaviour as **present-tense fact** about a thing that is not there — `crash.go` cited a dispatcher
file and a recover that no longer exist. The host had also reimplemented the framework's runtime API
**under its name**, `globalThis.runtime = { EventsOn }`, which a reader would reasonably take as
evidence the framework was still present.

Fixed before the cut. No file in the codebase names it; the reasoning survives as "the framework this
replaced", and `host.go` points at the decision record. The event shim is `globalThis.drmd.events.on`,
verified by driving the app, because `gate4_event_received` and `gate5_drop_delivered` are exactly the
two subscriptions it serves.

This is the same failure mode as the two false measurements corrected in the rev 5 handover: a true
statement about the past, left standing as a claim about the present. It did not fail a station
because no station asks whether the comments are true.

## C3 — Found by installing the DMG and using it

The premortem's one uncloseable line — install it and use it — closed, and it
returned a defect no station and no gate had seen: in the Code Block dialog,
*"the alignment between labels and fields here is off"*.

Measured at **+9.0px**. Every `.settings-row` is a two-line label beside a
control laid out with `align-items: center`, which centres the control against
the whole label group rather than the title it names. It was not local to the
dialog — the dialog reuses `.settings-row`, so all **13 rows** across it and the
Editor and Appearance settings carried it. All measure +0.0px now.

Two regressions surfaced while fixing it, both caught only because the test was
extended to control types the reported row does not contain:

| Control | Offset | Cause |
|---|---|---|
| Toggle | +6.0px | The band rule out-specified `.settings-toggle`, stretching the pill from 20px to 32px. |
| Segmented | +3.0px | `min-height` on a content-box element with 3px padding makes it 38px. |

**A stretched pill still centres correctly**, so the alignment assertion passed
it; its size is asserted separately for that reason. Measuring only the row that
was reported would have shipped both.

This is the second finding this release that arrived after the stations passed,
and like C2 it is not a station failure: no station asks whether the layout
reads correctly to a person, and no gate can. It is an argument for the
premortem line rather than against the review — the DMG step found what the
harness structurally cannot.

The tag was re-cut rather than followed by a patch: `v0.6.0` was tagged and
pushed but never published, so moving it cost nothing and shipping a known
cosmetic defect to be fixed hours later cost a release note.

## D — Verdict

**GO**, with three named residuals and one instruction: the remaining premortem line is that a
harness checks what someone thought to assert. Install the DMG and use the application before
publishing.
