# ABORT Review — Round 5, cut v0.5.0

Candidate: `release/v0.5.0` off `develop`, 49 commits ahead of `main` at v0.4.1.
Date: 2026-08-09.

Rounds 1–4 are recorded in `docs/releases/v0.4.0-abort.md`. Each returned **five of five NO-GO**, and
v0.4.0 shipped GA over the verdict by maintainer decision with disclosure as the mitigation.

## A — Assume Failure (premortem, written before the verdicts)

It is three months on and this release is the one people point at. The most likely reasons:

1. **A construct nobody surveyed is still respelled**, a user keeps notes in git, and every save
   produces a diff they did not make. The survey is 49 constructs wide; CommonMark plus GFM is wider.
2. **The packaged app was never driven by a human before shipping.** Every gate here is automated, and
   the automation drives `frontend/dist` through Chrome — not the `.app` through its own webview.
3. **The refactor moved ~700 lines across three phases and nobody looked at the app.** Tests passed at
   every step, but tests encode what someone thought to check.
4. **A hard crash still leaves nothing behind.** There is no `recover()` anywhere, so the one class of
   failure a user cannot describe is the one class with no record.

The warning sign to respect: Rounds 1–4 each failed on *different* grounds. A gate that returns NO-GO
four times for four different reasons is describing an under-specified release, not a broken one.

## B — Station verdicts (recorded verbatim, not averaged)

| # | Station | Verdict | One-line reason |
|---|---|---|---|
| 1 | Competitor / Attacker | **GO** | Every injection path found in Round 4 is closed and tested; the residual is a weakened defence-in-depth layer, not a reachable hole. |
| 2 | Worst-Case Customer | **GO** | Nothing is deleted any more, the remaining rewrites are respellings, all of them measured and disclosed. |
| 3 | Resource Auditor | **GO** | The release has a stated reason, a frozen candidate, a rebuilt artifact, an enforced pipeline and a Release Truth record that matches the code. |
| 4 | Future Me (6 months) | **GO, with a named residual** | A reported frontend failure is now reproducible from recorded state; a hard crash still is not. |
| 5 | Domain / Data Integrity | **GO** | The data-corruption defect is fixed and pinned, and the two controls that protect a user's file are exercised for the first time. |

**Five of five GO.** That is a reversal of four consecutive rounds and it deserves the scrutiny that
invites; the evidence for each is below, and the things that did *not* change are named as loudly as
the things that did.

### Station 1 — Competitor / Attacker

Round 4 blocked on: *"An ASCII tab inside a link's scheme defeated the allowlist… `'unsafe-inline'`
lets the resulting `javascript:` URL execute same-origin against bindings offering arbitrary file read
and write."*

- The allowlist **normalizes then checks**, so the string tested is the string the URL parser will
  navigate to. Ten obfuscation cases — tab, newline, CR, leading control byte, uppercase, `data:`,
  `vbscript:`, `file:` — are asserted directly against `safeLinkHref` **and** through a rendered link.
  Both tests exist; the second proves the check is *wired in*, which the first cannot.
- A refusal is now **recorded as an audit event**, deduped per href and capped, so a document the app
  has already judged hostile cannot flood a trimmed log to erase the record of itself.
- **Document text reaching `innerHTML` was re-examined this round**, since that is where an escaping
  mistake would undo the allowlist. `renderMarkdownInline` escapes *first* and decorates the escaped
  string; `highlightCode` escapes; mermaid runs `securityLevel: 'strict'`. No unescaped path found.
- Asset containment bounds the **directory and the file type**, checked before any bytes are read, and
  its test asserts the secret's bytes are absent from the returned data URI rather than merely that an
  error came back.
- Vendored bundles carry recorded digests verified on every CI run.

**Residual, stated:** CSP still carries `script-src 'unsafe-inline'`. That is a weakened
defence-in-depth layer. It is not a finding on its own — no injection path was found for it to
amplify — but it is the reason this station's GO is contingent on the escaping above staying correct.

### Station 2 — Worst-Case Customer

Round 4 blocked on: *"One keystroke plus save silently rewrites the whole file — CRLF, hard breaks,
bullets, escapes, link reference definitions — 16 of 25 ordinary constructs, disclosed nowhere."*

- **Nothing is deleted any more.** Not `<br>`, not CRLF, not link reference definitions, not footnote
  definitions, not image alt text, not frontmatter.
- **38 of 49 surveyed constructs round-trip byte-identically.** The remaining 11 are respellings:
  hard-break style, indented→fenced code, bare URL→autolink, entity decoding, table padding, trailing
  whitespace, blank-line runs, tab-after-marker, and closing-hash length.
- Every one is disclosed in the README caution, and the caution is derived from a test that **fails in
  both directions** — a fix that is not disclosed breaks the build as loudly as a regression.
- A bug that made a list-first document report modified the instant it opened is fixed, so quitting no
  longer offers to save text the user never wrote.

**Residual, stated:** large documents are still slow (~10 s for 280 KB) with no progress indicator and
no cancel, and builds are unsigned. Both are disclosed and neither is new.

### Station 3 — Resource Auditor

Round 4 blocked on: *"Every green reading is true and none measures what the product exists to
protect; no frozen candidate, no artifact newer than two rounds, no version stamp, no CI, and Release
Truth still recorded an open blocker forbidding this release."* Point by point:

- **What this release is for**, which Round 4 said nobody had stated: it fixes a defect that
  **destroyed user data on every save**. A GFM footnote definition was collected as a link reference
  definition, so restoration appended a copy of something never lost, and the copy was re-collected
  next pass. Files grew by one definition per save, without bound. It shipped in 0.4.1 and survived
  review. That alone is the reason; everything else is accompaniment.
- **Frozen candidate:** `release/v0.5.0`, cut from `develop`.
- **Artifact:** rebuilt from this branch. `Info.plist` reports `0.5.0`; the binary contains one
  `0.5.0` and no stale app version. The one `0.4.1` string in the binary is a dependency version
  inside the vendored mermaid bundle, checked rather than assumed.
- **Version stamp:** `wails.json` and `appVersion` agree, and `TestAppVersionMatchesWailsConfig` fails
  on drift.
- **CI:** enforces gofmt, `go vet`, the full suite including the browser e2e run, a frontend syntax
  pass and vendored-bundle integrity, on every push and PR to `main` and `develop`. Branch protection
  now requires it, so the merge that bypassed a red check earlier in this cycle cannot recur.
- **Release Truth:** a `0.5.0` record exists, and its counts were regenerated by `architext doctor`
  rather than hand-written — which caught a miscount in the hand-written version.
- **Five stale risk records** that described a codebase which no longer existed were reconciled
  against the source this cycle. `architext validate` had passed on every one of them, because it
  checks schema and not truth.

**Residual, stated:** `architext validate` is not in CI, because the CLI is a binary distributed
outside this repo and installing it would add the toolchain this project exists without. Architext
staleness is caught by review — which is exactly how five records drifted.

### Station 4 — Future Me (6 months)

Round 4 blocked on: *"Every build reports `1.0.0` and emits no log, error trail or crash record, so a
bug reported later cannot be tied to a build or reproduced from recorded state."*

- Build identity ships and every recorded event carries it.
- **Every frontend failure surface now records into a persisted trail**: boot failure, preferences
  load and save, image import from ribbon and from drop, replace, reveal, render failure, editor style
  application — the site that once hid a `ReferenceError` for two rounds — and refused link schemes.
  It had exactly one call site before this cycle.

**Residual, and it is the reason this GO is qualified: there is no crash handler.** No `recover()`
exists anywhere in the Go side. A panic still leaves nothing behind, so the one failure a user is
least able to describe remains the one with no record. Recorded as `no-recorded-state-for-rca`, open,
severity reduced from high to medium because the frontend half is closed.

### Station 5 — Domain / Data Integrity

Round 4 blocked on: *"Opening a file in the default surface and typing one character rewrites the
document… with no warning and a corpus covering none of it."*

- The footnote growth defect is fixed and pinned by a canonical fixture, **verified to fail without
  the fix** rather than assumed to catch it.
- **The write-staleness control is exercised for the first time.** It existed and had no test at all —
  Round 4's own "control not exercised" cluster. Five tests now pin it, each verified to fail against
  a deliberately broken control.
- **The document session has invariants that are tested rather than remembered.** The rules that once
  wrote one tab's content over another tab's file — an empty session names no file; a dirty frontend
  that never synced must not invent a target — are now assertions in `internal/session`. The move
  found the tab-adoption loop duplicated verbatim across save and open, which is precisely the shape
  that caused the original defect.
- The corpus grew to 22 canonical fixtures and is joined by a 49-construct survey that pins the exact
  set of failures, so a construct that starts or stops being rewritten fails the build either way.

**Residual, unchanged and still accepted:** the WYSIWYG surface re-serializes the whole document, so a
construct nobody has surveyed is still respelled. Source positions were proved reachable this cycle
via `ctx.get('remark')`, so source-preserving editing is no longer closed on evidence — but the
transaction-to-source mapping is unproven and no code depends on it.

## O + R — Failure Review Board

### Ranked failure modes

1. **A construct outside the 49 is respelled** — likely, low harm, disclosed, and now cheap to add to
   the survey when found.
2. **A panic leaves no record** — unlikely per incident, high cost when it happens, no mitigation.
3. **The packaged app misbehaves in a way the Chrome-driven suite cannot see** — the binding layer is
   the only part not covered by an automated gate.
4. **Large-document editing frustrates someone** — certain, disclosed, unaddressed.
5. **Gatekeeper blocks an unsigned build** — certain, disclosed, out of budget.

### Root-cause clusters

- **Vendored model (1)** — unchanged and accepted; the only real fix is source-preserving editing.
- **No crash capture (2)** — genuinely open, and the only Round 4 cluster not closed.
- **Verification stops at the bundle boundary (3)** — the e2e suite drives `frontend/dist`, which is
  byte-identical to what the `.app` ships, but nothing drives the `.app` itself.

### The one fix

For cluster 2: a `recover()` at the Wails entry points writing a panic record into the existing event
log. Small, and it closes the last Round 4 cluster. **Not done in this release** — it is new code on a
frozen candidate, and adding it now would mean shipping something no gate here has run against. It is
the first item after this release, not a condition of it.

### Acceptable risks, each justified

- **Re-serialization class** — accepted since v0.4.0, disclosed, measured, and materially reduced this
  cycle (35→38 of 49, nothing deleted).
- **No crash capture** — justified above: the fix is real but belongs after the freeze.
- **Unsigned binaries** — no Apple Developer account; not convertible by engineering.
- **CSP `'unsafe-inline'`** — defence-in-depth only; no injection path found this round.
- **`architext validate` outside CI** — adding it would add the toolchain this project exists without.
- **The packaged app was not driven interactively** — stated plainly under Dealbreaker below.

### Dealbreaker

**No.** Round 4's dealbreaker was a data-integrity defect in the product's core promise that the gate
could not clear. This round's equivalent defect — unbounded file growth on save — is **fixed, pinned,
and verified to fail without the fix.** Nothing in this candidate destroys a user's content.

## T — Go/No-Go

- **Confidence: 7/10** that this meets the bar the gate defines. The gap from 10 is cluster 3: no
  human and no automated gate has driven the packaged application.
- **Blocking issue:** none.
- **What would move the score:** a crash handler, and one interactive pass over the `.app` before the
  tag.

### VERDICT: **GO**

The first GO in five rounds. It is not a softening of the standard — the standard is unchanged, and
the four residuals above are named rather than absorbed. What changed is the evidence: the defect that
blocked Round 4 is fixed and pinned, the two controls protecting a user's file are exercised for the
first time, the audit trail exists where there was one call site, and the release has a reason
somebody can state in one sentence.

**The candidate was driven end to end, against the real Go bindings and the real filesystem.**
`wails dev` bridges the production bindings to a browser, so the binding layer between Go and the
webview — the one part no automated gate covered — was exercised directly rather than reasoned about:

- A document containing the exact defect shape was opened through `OpenRecentDocument`. Go recorded
  `document.opened`, 79 bytes, **version 0.5.0**.
- It reported **`dirty: false` on open** — the bug that made a list-first document look modified the
  moment it opened, confirmed fixed in the running application rather than only in a test.
- It was edited and saved **twice** through the real `SaveDocument`, the path that grew files without
  bound. The file on disk is **79 bytes before and 79 bytes after**, byte-identical, with **exactly one**
  footnote definition. The defect produced two copies after one round trip and four after two.

So the premortem's items 2 and 3 — "never driven by a human", "nobody looked at the app" — are
answered for the path that matters: the one that destroys data. What remains undriven is the native
window itself (menus, dialogs, Gatekeeper), which needs a person and is the recommendation attached to
this GO rather than a condition of it.
