# ABORT review — v1.6.1, "Repair from use and the standing defect backlog"

Reviewed against `release/v1.6.1`. Every claim below was measured at review time;
where a number appears, the command that produced it is implied by the claim.

## A — What this release is

The first release **scoped from using the packaged application** rather than
from review findings or the issue tracker.

v0.6.0's premortem carried one line a harness cannot close — *install the DMG
and use it*. Closing it immediately returned a layout defect that five ABORT
stations, the host gates and a 40-check screen walk had all passed over, and
then five more findings in the same way. Alongside those, this release clears
the **entire standing defect backlog**: every open issue that was a defect
rather than a roadmap milestone.

Ten required items, all complete. Nothing deferred.

**Five of five GO, with two named residuals.**

### Station 1 — Competitor / Attacker

Checked rather than asserted:

- `Content-Security-Policy` **unchanged since `main`**.
- The only `fetch()` in the frontend is `vendor/theme/manifest.txt`, a local
  path. No `XMLHttpRequest`, no `WebSocket`.
- `verify-vendor.sh` accounts for **29 files**, unchanged in count from v0.6.0.

**One new global.** `globalThis.drmd.normalizeLanguage` is exposed so the
vendored bundle can reach the app's own normalizer (#78). It is a pure string
function over a language name, it is read by the bundle rather than written, and
the alternative — spelling the mapping out inside `tools/vendor.sh` — would have
put a product decision in a shell script that rewrites a third-party artifact.

**The event-log fold was examined as a suppression primitive** and is not one.
Folding could in principle be a way to make a repeated action disappear from an
audit trail. It cannot: a folded event still records at decade milestones
carrying its count, so the trail says *what* happened and *how many times*, only
not once per occurrence. At most 64 distinct signatures are tracked, past which
events record **unfolded** — a flood spread across many distinct signatures
falls back to recording everything rather than to suppressing more.

**Residual:** the Crepe bundle is now patched in **six** places and matches no
upstream artifact. The digest file is its only provenance, which is why
`verify-vendor.sh` runs on every push. Each patch fails loudly with an
explanation of what breaks if its anchor moves.

### Station 2 — Worst-Case Customer

The customer who will feel this release most is one who knows where things were.

Measured by diffing every `data-command` between `origin/main` and this
candidate: **21 before, 21 after, empty diff.** Nothing was lost, moved or
renamed in the ribbon.

The menu gained exactly one item, `View > Reveal Image in Finder`, which
restores a route that v0.6.0 removed.

**The icon changed identity**, and that is the most visible change in the
release. The previous artwork is gone rather than adjusted: a stethoscope looped
through the mark, which was unreadable at Dock size and was two different
artworks at different sizes. Someone who liked it has lost it.

**Raised as a residual, and withdrawn.** This review recorded that the
application's `--accent` was tuned to the *previous* icon's hue, so the in-app
accent and the new artwork are no longer the same blue, and carried it as
something to correct.

The maintainer ruled otherwise: **an application's icon and its internal theme
are not required to match.** They are seen in different places, by different
means, and holding them to one hue is a constraint nobody asked for. Recorded
here so a later review does not derive the same finding again — the divergence
is deliberate, not drift.

### Station 3 — Resource Auditor

- `VERSION` is the single source. The bundle reports `1.6.1` for both
  `CFBundleShortVersionString` and `CFBundleVersion`, matching the file.
- Ten required items, **zero deferrals**. Nothing in this release is postponed,
  so there is no deferral to justify.
- The five open roadmap milestones are recorded as out of scope **with the
  reason**: they are multi-release trackers, not defects.
- 248 test functions; full `go test ./...` green including a 122s e2e suite;
  host gates, 40-check UI walk, menu check and close guard all PASS.

### Station 4 — Future Me (6 months)

The question this station asks is whether a reader in six months can tell why,
not just what.

Every fix in this release records its **measurement**, not its conclusion: +9.0px
of misalignment, 4-versus-2-space indentation, 20px of overflow, 5000 repeats
producing 2000 records, a panic leaving no file at all. A future reader can
re-run every one of them.

Every **rejected alternative** is recorded with its reason, which matters more
than the chosen one:

- Fence casing was not fixed on serialize, because that rewrites fences the user
  authored — asserted by a test that opens a document containing `Python` and
  requires it back unchanged.
- Reveal was not put on the image block, because that block is vendored and
  injecting into DOM the node view rebuilds is the pattern behind #77 and #80.
- The startup panic guard **re-panics** rather than rescuing, because continuing
  into a half-built application trades a visible crash for an invisible one.
- The global `box-sizing: border-box` was **not** adopted, though two defects in
  this release were content-box overflows, because ~2300 lines of CSS were tuned
  without it and the blast radius wants its own change.

### Station 5 — Domain / Data Integrity

The fidelity guarantee is **stronger than it was**, which is unusual for a
release that changed how fences are written.

Before this, one direction was asserted: the picker's behaviour was pinned so it
could not change unnoticed. Now both are. A document opened with ` ```Python `
and ` ```JavaScript ` must come back with both unchanged — a document comes back
as it went in, whatever the app would have written itself. That test did not
exist before and is the reason the fix is at the picker rather than on serialize.

The event log's bound changed shape but not its contract: it is still bounded,
still keeps the newest, and still swallows every failure to write.

## C — Premortem

*It is three months from now and this release went badly. What happened?*

1. **The icon.** It is the one change every user sees and nobody asked for. The
   old one was replaced because it was unreadable at Dock size, which is a real
   defect, but "unreadable" was a judgement and the replacement is another one.
   *Mitigation: none available. It is a taste call made by the maintainer with
   the artwork they supplied.*

2. **A folded event hides something in an investigation.** A defect recurs with
   slight variation, each occurrence just distinct enough to consume a signature
   slot, and past 64 the fold stops applying — so the flood returns in the exact
   case where diagnosis matters. *Mitigation: falling back to unfolded is the
   safe direction; nothing is lost, the trail just fills as it used to.*

3. **The startup recover masks a startup failure as a runtime one.** It records
   `operation: startup` with a `phase` field precisely so the two cannot be
   confused, but a reader who ignores the phase would misread it.

4. **Install-by-identity removes something it should not.** It reads the
   identifier from the bundle being installed and checks every candidate before
   removing it, verified against decoys — but it is `rm -rf` against paths in
   `/Applications`, and that is the most destructive line in the repository.
   *Mitigation: it refuses to run at all if the bundle has no identifier.*

5. **The one a harness cannot close, again.** Install the DMG on a clean machine
   and use the application. v0.6.0's premortem carried this line, closing it
   returned six defects, and this release exists because of them. It carries the
   same line for the same reason.

## D — Verdict

**GO.**

Five of five stations GO, with **one** named residual: the vendored bundle is
patched in six places and matches no upstream artifact, so its digest file is its
only provenance.

A second was raised — that the in-app accent no longer matches the icon — and
withdrawn on the maintainer's ruling that the two need not match. See Station 2.

The premortem's first line — the icon — is a taste judgement rather than a
defect, and is the maintainer's own. Its last line is the one that matters, and
it is unchanged from v0.6.0: **install it and use it.** That is not a formality
here. It is where every item in this release came from.
