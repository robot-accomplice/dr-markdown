# ABORT review — v1.6.2, "The application is named Dr. Markdown"

A short review for a short release: one user-facing fix and one cleanup. The
stations are the same five; the evidence is proportionately smaller because the
surface changed is.

## A — What this release is

1.6.1 was installed and used, which is what 1.6.1 existed to make possible. The
first thing it produced was a naming defect: the application presented itself as
**"dr-markdown"** in the launcher and in the application menu.

Cut as its own release rather than held, because the maintainer is about to
settle on a version and live with it, and that version should not be one that
gets its own name wrong.

## B — Stations

**Five of five GO. No new residuals**; the two carried from 1.6.1 stand.

### Station 1 — Competitor / Attacker

Nothing executable changed. The diff is a bundle filename, an executable
filename, two file deletions and three corrected records.

`codesign --verify --deep --strict` passes over the renamed executable — worth
checking rather than assuming, since the signature covers the bundle's contents
and the executable's name is part of its structure.

The two deleted files were confirmed unreferenced before removal, and the build
was re-run without them.

### Station 2 — Worst-Case Customer

**This release's entire risk is the rename.** Renaming an installed application
normally strands the previous copy: `/Applications/dr-markdown.app` would survive
beside `Dr. Markdown.app`, both claiming `com.drmarkdown.app`, and LaunchServices
resolves a double-clicked `.md` by identifier rather than by path. The user would
get whichever one macOS picked, one release behind, with nothing in the window to
say which.

**That is not hypothetical — it is exactly what was reported during 1.6.1**, from
a `Dr. Markdown.app` at 0.5.1 sitting beside a fresh install.

It cannot happen here, because installing now replaces by **identifier**, not by
path. That fix shipped in 1.6.1, one release before the change that needed it.

### Station 3 — Resource Auditor

`VERSION` is 1.6.2 and both plist version keys follow it. Two required items,
zero deferrals. CI gained an assertion that the bundle's filename matches
`CFBundleName` — the check whose absence let the file and the plist disagree for
several releases.

### Station 4 — Future Me (6 months)

The trap here is that **three names look interchangeable and are not**:

- `CFBundleName` / `CFBundleDisplayName` — said "Dr. Markdown" throughout, and
  govern neither place that was wrong.
- The **bundle filename** — what Finder, Launchpad and Spotlight display.
- The **executable filename** — what AppKit puts in the application menu, because
  it takes the process name there.

A future reader changing one of these will find the other two recorded beside it,
in `tools/build-macos.sh` where the decision lives.

### Station 5 — Domain / Data Integrity

No document path, serializer, fidelity policy or preference was touched. The
event log is unchanged.

## C — Premortem

*It is three months from now and this release went badly. What happened?*

1. **A stale `dr-markdown.app` survives somewhere the installer does not look.**
   Replace-by-identity scans `/Applications` and `~/Applications`. An app kept
   anywhere else is invisible to it. *Mitigation: none, and it is worth knowing
   rather than pretending otherwise.*

2. **The space in the path breaks something unquoted.** Every `$APP` use in the
   build script was already quoted and the CI assignment was fixed, but a future
   script that is not will fail in a way that reads as a missing file.

3. **The removed `appicon.png` turns out to have been wanted.** It was the old
   icon and nothing consumed it, but "nothing consumed it" is a claim about the
   repository, not about the maintainer's intent. *Mitigation: it is one `git
   revert` away and named in the commit.*

## D — Verdict

**GO.**

The release exists because 1.6.1 was installed and used. That its first finding
was the application's own name is not a criticism of the review that shipped it;
no station asks what the Dock says, and no gate can see a launcher.

The premortem line is unchanged and is once again the point: **install it and
use it.**
