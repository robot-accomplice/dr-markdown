# ABORT review — v1.7.0, "Desktop integration and packaging hardening"

**Decision under review.** Ship dr-markdown v1.7.0 from frozen SHA `13ca5c0`
(branch `release/v1.7.0`) as public, Developer-ID-signed, notarized macOS
`.dmg`s (arm64 and universal), replacing v1.6.3.

**Reversibility and blast radius.** The tag and the GitHub release are
revertible. **A downloaded binary is not**, and this product has no
auto-update — a defect that ships stays on a user's machine until they choose
to download a later release. The exposed party is anyone who opens a markdown
file with it, and the untrusted input *is* the document.

**Why this review reads differently from the last one.** v1.6.3's review found
a dealbreaker written by the previous review's remedies. This release's defect
work is narrower — four repairs to the WYSIWYG surface's behaviour under zoom
and mode switches, every one of them found by the maintainer's eye during host
verification, and every one written during the ceremony itself by the same
agent that shipped the defects. The marquee repair (remote-image chips)
shipped its first version broken — empty lozenges, caught only by that same
eye. That is the shape this review had to defend against.

## A — Premortem

> We shipped, and it failed because the marquee repair shipped its first
> version broken — empty lozenges, caught only by the maintainer's eye — and
> every repair in this release was written during the ceremony itself, by the
> same agent that missed the defects the first time. The second version
> replaced a broken `<img>` with foreign DOM inside ProseMirror's live inline
> content, and nobody typed in the badge paragraph afterward; the first save
> after any edit dropped every badge from the user's README.

**The sentence that would have stopped the ship:** *"The chip replacement
mutates DOM that ProseMirror owns, and nobody typed in the badge paragraph
afterward."*

The premortem's failure did not happen — the round-trip test written to close
it passes (see C1) — but it was the right fear: it is the one mechanism in
this release that could destroy user data on save rather than merely render
wrongly.

### Claims verified before being believed

Two station claims were checked against the tree rather than trusted:

- **The open-issue list** (station 4). `gh issue list` confirms exactly issues
  5, 10, 11, 12, 13 and 160 open. The probe follow-up had never been filed.
- **The unconditional `__probe` dispatch** (station 3). `dispatchCall`
  (`host_darwin.go:463-499`) routes `Ping`, `Boom`, `__gates`, `__realdrop`,
  `__walk`, `__probe`, `__doc`, `__closenow` and `__quitnow` in a switch with
  no harness-flag guard. `reportProbe` (`probe_darwin.go:721`) calls
  `os.Exit(1)` on an unreadable payload and runs `screencapture` when
  `probeImg` is set. v1.6.3 made the *injected driver* conditional; the
  Go-side dispatch was never checked. Filed as #161.

## C — Failure review board

### Ranked failure modes

| # | Failure mode | Trigger / mechanism | Sev | Lik | Det | Risk | Cluster | Call |
|---|---|---|---|---|---|---|---|---|
| 1 | Editing a chipped paragraph loses the badge on save | The chip is foreign DOM where ProseMirror's document model still holds the image; if the editor ever reconciles the mutation inward, serialization drops the image or gains stray alt text | 4 | 2 | 2 | **16** | foreign DOM | BLOCK → C1 |
| 2 | Chip reverts to a blank box after a redraw | ProseMirror recreates the img when it redraws the node; re-chipping only runs on the next render pass | 2 | 3 | 1 | 6 | foreign DOM | ACCEPT |
| 3 | No-alt chip shows the raw URL | `img.alt` empty → chip text falls back to the source URL | 1 | 3 | 1 | 3 | foreign DOM | ACCEPT |
| 4 | Gate-runner methods reachable from page JS | Unconditional dispatch switch; `__probe` exits the process on a bad payload | 3 | 1 | 2 | 6 | harness in binary | ACCEPT → #161 |
| 5 | Close-guard diverges from the editor | `pushDirtyState` fires `bridge.setDirty` and advances `lastPushedDirty` before the promise settles; a rejected or reordered push is never retried | 4 | 1 | 1 | 4 | fire-and-forget | pre-existing → #162 |
| 6 | Vendor silent-failure class | A bare `@import` surviving the rewrite fails silently; no upstream integrity pinning; the resize handle is disabled by ungated CSS | 2 | 2 | 3 | 12 | build hygiene | follow-up → #163 |

### Root-cause clusters

1. **Foreign DOM inside the editor's own tree** (1, 2, 3) — the chip repair
   deliberately mutates DOM that ProseMirror owns, trading a rendering defect
   for a correctness question. Leverage point: prove serialization from the
   document model, which is the only thing save reads.
2. **Harness reachability** (4) — v1.6.3 conditioned the driver and stopped;
   the dispatch it drives was never audited.
3. **Fire-and-forget bridge pushes** (5) — optimistic bookkeeping ahead of an
   unsettled promise, in the one flag the close-guard trusts. Pre-existing.

### The one fix

**One e2e test that edits across a chipped paragraph and asserts serialization
survives.** That single gate neutralises finding 1 — the only mechanism in
this release that could corrupt a saved file — and converts station 5's proof
from "true today, by inspection" into "enforced forever, by a gate that can
fail."

### Acceptable risks

- **Chip re-application gap (2).** If ProseMirror redraws the node between
  render passes, the img returns — and with it the zoom-collapsed placeholder
  — until the next render re-chips it. Cosmetic, self-healing, and bounded by
  the render queue the app already serializes.
- **No-alt chips show the URL (3).** Cosmetically worse than alt text,
  strictly better than the blank box it replaced.
- **Harness channels ship, argv/env-gated inert (4).** The deliberate v1.6.3
  trade — the harness must drive the same binary a user gets — now extended to
  a verified fact about the dispatch. Filed as #161 so the decision is
  tracked, not accidental.
- **Vendor follow-ups (6).** The `@import` silent-failure class and the
  missing upstream pinning are real but pre-date this release; filed as #163.
- **The zoom/mode morph sweep's 2% tolerance.** Calibrated to the defect class
  it guards (layout drift under zoom/mode switches); it will not catch
  sub-perceptual shifts, which are not this release's defect class.

### Dealbreaker

**NO.** The only candidate was finding 1, and it is closed by a gate that ran
red before it ran green — the strongest evidence a gate is load-bearing.

## Closure

**C1 — the convergent condition.** The new gate places a caret at the end of
the chip's paragraph and inserts text through the browser's real editing
pipeline, then asserts on `getEditorMarkdown()`. Its first run failed, and the
failure is worth recording: the image survived intact, but the inserted text
landed *inside* the link — `[![License: MIT](…) edited](LICENSE)` — because a
caret at the paragraph's end sits on the link's trailing edge, which is
ordinary link-edge behaviour for any link, chip or not. The assertion was
recalibrated to the actual invariant — image, alt, URL and link target
verbatim; alt text appears exactly once; the edit lands — and the gate now
passes. A gate that ran red first is the only kind worth trusting.

**C2–C4 — the filings.** #161 records what v1.6.3's closure left unverified:
the injected driver was conditioned on the harness flag, but the gate-runner
dispatch it drives was not, and `__probe` can exit the process from page JS.
The issue offers both fixes (flag-gate the switch; build-tag it out) and names
the rule the second one would amend. #162 records the dirty-push race and its
close-guard consequence. #163 collects the vendor hardening items, including
the one WebKit-shaped caveat: the Chrome-based gates cannot catch a
WebKit-only chip regression, so the chip's rendering is verified by host
eyeball, and the first cheap WebKit smoke assertion should target it.

**C5** is discharged at publish: #160 closes when the release that fixes it is
public, and the release detail's statuses flip from in-progress to complete in
the same close-out.

### Found while closing the conditions

Nothing new. The one red the convergent gate ever showed was a wrong
assertion, not a defect — recorded above precisely because "the gate failed
and the gate was wrong" is the finding most likely to be forgotten by the next
review.
